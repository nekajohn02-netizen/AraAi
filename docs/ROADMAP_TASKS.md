آخر تحديث: 2026-11-25

## 1. الهوية والقرار

ARA = **Personal AI Operating System for Android**: محلي أولًا، عربي أصلًا، قادر على تنفيذ مهام، خصوصية قابلة للتحقق، قابل للتوسعة.

لن نتنافس على عدد النماذج أو الأزرار. سنتفوق في قدرات محددة **مثبتة بقياسات قابلة للتكرار**:
1. جودة العربية والبحث الموثق في الملفات.
2. ذكاء اختيار النموذج (حسب قدرات مُختبَرة لا بيانات تسويقية).
3. تنفيذ المهام بأمان (الصلاحيات خارج النموذج).
4. خصوصية يمكن فحصها.

الأولوية الصريحة: **لا متجر مهارات ولا اشتراكات ولا Telegram الآن.**

## 4. القرارات المعمارية الجديدة

1. Rust حيث يضيف قيمة (توجيه، استرجاع، أدوات، نماذج)؛ Kotlin لدورة حياة Android والصلاحيات والواجهة.
2. طبقة `InferenceEngine` موجودة؛ أي محرك جديد (LiteRT-LM، ExecuTorch) لا يُعتمد قبل إثباته على الأجهزة المستهدفة.
3. النواة تقرر الأمان؛ النموذج يقترح فقط (مُطبّق في `dispatch`).
4. التقييمات قابلة للتكرار: نفس الجهاز/النموذج/التكميم/السياق، وتُحفظ النتائج.
5. لا ندّعي الخصوصية لمجرد أن النموذج محلي: نفحص الشبكة والسجلات والنسخ الاحتياطي (مهمة T1.7).

### P1 — فروق جوهرية

- [ ] **T1.1 — Knowledge Vault (مرحلة 1):** استخراج PDF (ثم DOCX/EPUB)، رقم الصفحة في الاستشهاد، حذف مكرر/إصدارات. *القبول:* استشهاد برقم الصفحة الصحيح على 20 سؤالًا من مجموعة PDF اختبارية.
- [x] **T1.2a — تقاطع لهجات/لغات بلا تدريب (تم 2026-11-25):** قرار صاحب المشروع: لا تدريب/ضبط يدوي لموديل من أجل اللهجة — يستنزف GPU ومجموعة بيانات ويبقى خطرًا على رام الهاتف. البديل: `core/lexicon/ar_crosswalk.json` (جدول ثابت مصري/فصحى/إنجليزي، مُعدَّل كبيانات لا كود) + `learned_aliases` (تعلّم بتأكيد المستخدم الصريح فقط، سقف صارم 2000 صف مع إخلاء الأقل استخدامًا). التوسيع عند الاستعلام فقط (OR، حد 24 حدًا)، لا تغيير على الفهرس. تكلفة المعالج تذكر صفريًا (لا نموذج يعمل). *القبول:* `اريد` يجد مستندًا فيه فقط `عايز`، و`الذكاء الاصطناعي التوليدي` يجد مستندًا فيه فقط `Generative AI` — دون أي حمل على الرام/التخزين بما يتجاوز عدة كيلوبايتات. **النتيجة:** منفَّذ ومُختبر (20 اختبارًا في `ara-search`)، التفاصيل في `docs/ARCHITECTURE.md` ADR-013.
- [ ] **T1.2b — البحث الدلالي + Reranking (تضمينات):** نموذج embeddings **جاهز ومُدرَّب مسبقًا** (مرشح: Qwen3-Embedding-0.6B) — لا تدريب محلي — مع بوابة تفعيل حسب فئة الجهاز في `ara-device-profiler` وسقوط آمن للبحث النصي+crosswalk وحدهما على الأجهزة الضعيفة. *القبول:* Recall@5 وMRR أعلى من FTS+crosswalk وحدهما على مجموعة عربية/إنجليزية، مع قياس رام فعلي قبل/بعد التفعيل.
- [ ] **T1.3 — مجموعة تقييم الاسترجاع:** أسئلة + إجابات + مصادر صحيحة لقياس Recall@K وMRR وصحة الاستشهاد. *القبول:* تُشغَّل بأمر واحد.
- [ ] **T1.4 — Agent OS: تخطيط وDry-run:** الخطة تُعرض كخطوات قابلة للمراجعة قبل التنفيذ؛ معاينة (dry-run) للأفعال المؤثرة؛ سجل تنفيذ واستئناف بعد الانقطاع. *القبول:* سيناريو «لخّص ملفات المحاضرات واعمل ملف مراجعة» ينجح بخطوات موافَق عليها.
- [ ] **T1.5 — Memory Graph:** كيانات (تفضيلات، مشروعات، أشخاص) + مصدر + ثقة + تاريخ + انتهاء صلاحية + مساحات عمل + حذف موثوق. *القبول:* اختبار حذف يثبت اختفاء المعلومة من كل المخازن.
- [ ] **T1.6 — Voice:** STT محلي (Whisper) ثم TTS؛ مكوّن مستقل عن LLM؛ مقاطعة الكلام. *القبول:* تحويل عربي مصري بنسبة خطأ مقاسة (WER).
- [ ] **T1.7 — Privacy Center + Strict Offline Mode:** سجل لكل طلب (محلي/سحابي، ملفات، أدوات)، منع الشبكة عدا استثناءات يوافق عليها المستخدم، فحص السجلات والنسخ الاحتياطي. *القبول:* اختبار يثبت عدم وجود اتصال شبكي أثناء وضع Offline (فحص عبر الـ proxy/ملف الاتصالات).
- [ ] **T1.8 — تشفير البيانات:** تشفير `index.db` والمحادثات بمفتاح Keystore (مثلًا SQLCipher أو تشفير ظرفي). *القبول:* ملف التخزين غير مقروء بدون المفتاح؛ اختبار استعادة.
- [ ] **T1.9 — تقوية ضد Prompt Injection:** مجموعة هجمات (مستندات، صفحات، نتائج أدوات) تُشغَّل آليًا. *القبول:* 0 أفعال مؤثرة تُنفَّذ بدون موافقة في كل الحالات.
