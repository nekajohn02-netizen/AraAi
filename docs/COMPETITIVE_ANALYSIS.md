# ARA — Competitive Analysis (T0.4, Verified)

**Research date:** 2026-11-25
**Method:** Direct review of each competitor's own GitHub repository (source code, commit history, releases, README/docs), official product pages, and the Google Play listing for Qandeel. No competitor app was installed or hands-on tested. GitHub API (`gh api`) was used to pull repo metadata, commit logs, release tags, README files, and to grep source trees for specific features (localization files, encryption code, MCP/skills folders, etc.) rather than trusting marketing copy.
**Supersedes:** The competitor table in `docs/ROADMAP_TASKS.md` §2, which was explicitly flagged there as unverified (pasted from another AI's analysis, not checked against source). This document is the verification task (T0.4) referenced in that file. Where this document's findings disagree with that table, trust this document.
**Later update (same day, 2026-11-25):** `reports/تحديث تحليل منافسين ARA.md` re-checked this analysis a few hours later and found one material change — Google AI Edge Gallery shipped real AES-GCM at-rest encryption (commit `1c7b534`, 2026-11-12), the first found in any open-source competitor here — plus a new investigation item (the Nile-Chat Egyptian-Arabic model family) and a revised P1 roadmap ordering. Where the two disagree, trust the later report.

**Classification used for every claim below:**
- 🟢 **Verified** — confirmed in the competitor's own source code, commit/release history, or detailed official technical docs.
- 🟡 **Advertised** — stated only on a marketing/product page or app-store listing; no source access to confirm, or wording too vague to confirm.
- ⚪ **Unverified/unclear** — contradictory, stale, or insufficient evidence either way.
- ⬛ **Not found** — actively searched for in source and found no evidence of it (does not prove absence, especially where GitHub code search is known to be incomplete, but no supporting evidence exists).

## 2. Per-competitor detail

### 2.1 AnythingLLM Mobile

- **Repo:** https://github.com/Mintplex-Labs/anythingllm-mobile (checked 2026-11-25) — GPLv3 (releases ≥1.2.0; MIT before that), TypeScript 2.2M lines + Kotlin 212K + JS/ObjC. 211 stars, 19 open issues, last push **2026-11-24**, 5 of 5 most recent merged PRs are real bug fixes with detailed root-cause write-ups (crash fixes, memory-leak fix in workspace sync) — this is a sign of active, disciplined maintenance, not just feature churn.
- **Strengths (verified from README/source):**
  - By far the broadest **provider matrix** of any local-first competitor reviewed: on-device GGUF plus 10+ cloud/LAN backends (Ollama, LM Studio, LocalAI, Lemonade, llmman, LiteLLM, plus Anthropic/OpenAI/Gemini/DeepSeek/etc.), all sharing one agent harness.
  - Deep **OS-level integration**: can register as the phone's default digital assistant (overlay invocable from any app), a "share to AnythingLLM" target, and a text-selection toolbar action in other apps — none of the other five competitors claim anything like this.
  - Background **scheduled jobs** that survive app closure, with lock-screen notification on completion.
  - On-device RAG described in detail (embedding + vector DB + reranking all local) and document generation (Word/PDF/PPTX/text) from a conversation.
- **Weaknesses/limitations (verified):**
  - **No Arabic localization at all** — confirmed by reading `src/locales/languages.json`: 17 languages (en, de, es, fr, hi, id, it, ja, ko, nl, pl, pt-BR, ru, tr, vi, zh, zh-TW), Arabic absent.
  - Voice input relies on the **phone OS's** native speech recognizer, not a bundled offline model — so "voice input" quality and offline-ness depend on what Android ships, unlike PocketPal/Private Mind's bundled Whisper.
  - No encryption-at-rest evidence found for local chat/document storage.
  - GPLv3 licensing (copyleft) is a real constraint for anyone wanting to reuse its code commercially, unlike the MIT/Apache competitors.
- **Evidence:** repo metadata/commits/releases via `gh api repos/Mintplex-Labs/anythingllm-mobile` (checked 2026-11-25); README at https://github.com/Mintplex-Labs/anythingllm-mobile/blob/main/README.md (checked 2026-11-25); locale file https://github.com/Mintplex-Labs/anythingllm-mobile/blob/main/src/locales/languages.json (checked 2026-11-25).

### 2.2 PocketPal AI

- **Repo:** https://github.com/a-ghorbani/pocketpal-ai (checked 2026-11-25) — MIT license, 9,786 stars (by far the most of any open-source competitor here), 141 open issues, last push **2026-11-23**, releases roughly weekly (v1.24.0 on 2026-11-17, v1.23.0 on 2026-11-10, etc.) — the most consistently-paced release cadence of the group.
- **Strengths (verified from README/source/commit history):**
  - Genuinely detailed, audited **4-layer architecture** documented in the README (UI/Tool-use → Bridging → Engine → Hardware) with exact pinned versions (`llama.rn 0.13.0-rc.11` → llama.cpp b12292, `whisper.rn 0.7.4`, ONNX Runtime for TTS). This is one of the most transparent technical READMEs of the six.
  - Real, bundled **on-device TTS with 4 distinct neural engines** (Kokoro, Kitten, Supertonic, Phonon) plus system voices — the richest voice-output story of any competitor reviewed.
  - **ar.json confirmed with real Arabic strings** (e.g. `"cancel": "إلغاء"`, `"delete": "حذف"`) — among 16 shipped UI languages. Some values are left untranslated/English inside the Arabic file (e.g. `"second": "sec"`), suggesting partial/community-translation quality, not professionally localized.
  - Transparent **privacy note** in the README distinguishing exactly which network calls happen and why (model/voice downloads, PalsHub, device-compatibility rules from a CDN, opt-in leaderboard) vs. chat content (never sent anywhere unless the user turns on web search or a remote server).
  - Public, opt-in **device leaderboard** (pocketpal.dev/leaderboard) for tok/s and memory — the only competitor with a public cross-device benchmark database.
- **Weaknesses/limitations (verified):**
  - **No document/RAG chat feature found anywhere in the README's feature list** — PocketPal's "Talents" are calculator/datetime/render_html/web_search/read_url only; attaching a PDF/document and asking questions about it is not described. This is a real functional gap versus AnythingLLM Mobile, Private Mind, and (claimed) Qandeel.
  - Chat history lives in plain **WatermelonDB**; the README's own tech-stack table puts only "secrets" in Keychain, not conversation content — no at-rest encryption claim for chats.
  - The richer features (hands-free voice mode, local API server) are gated behind the paid **PocketPal Plus** one-time purchase on the App/Play Store builds (free only in from-source or GitHub-release-APK builds after v1.23.0) — "free and open source" has an asterisk for most real users who install from the stores.
- **Evidence:** repo metadata/commits/releases via `gh api repos/a-ghorbani/pocketpal-ai` (checked 2026-11-25); README https://github.com/a-ghorbani/pocketpal-ai/blob/main/README.md (checked 2026-11-25); locale file https://github.com/a-ghorbani/pocketpal-ai/blob/main/src/locales/ar.json (checked 2026-11-25).

### 2.3 Layla

- **No public source for the main app.** Extensive search found no GitHub repo for the Layla Android/iOS app itself. The only public repo is the **Layla SDK** (https://github.com/l3utterfly/layla-sdk, checked 2026-11-25), Apache-2.0, 37 stars, last push 2026-11-18 — a TypeScript SDK for building WebView "mini-apps" that run inside the closed-source host app.
- **What the SDK source actually confirms (🟢 Verified, indirectly):** the SDK's own README/API surface documents real host capabilities that mini-apps can call: chat with tool calling and multimodal image input, streaming, character-chat state, "out-of-band" side questions, inference-engine selection, scheduled messages, TTS playback and audio-file generation, STT microphone input, background audio, image generation, image-to-video and text-to-video generation (named models: NeoDragon, Nightmare Mobile/WAN, Ace-Step for music), a private per-mini-app SQLite database, and Layla Cloud sign-in. Because this is a real, consumable API contract (not marketing copy), the *existence* of these host features is more credible than a typical landing-page claim, even though the main app's implementation is unverifiable.
- **Everything else is 🟡 Advertised only**, from https://www.layla-network.ai/local-llm-android (checked 2026-11-25): multi-engine support (llama.cpp/GGUF + LiteRT-LM + ExecuTorch .pte "behind one interface"), i8mm hardware acceleration, Qwen3-VL vision, MCP support, on-device Python execution with no server/API key, long-term memory, Stable Diffusion image generation, "Layla Server" (your own PC as a backend), and comparisons against ChatterUI/PocketPal. None of this is checkable without the app's source.
- **Pricing:** App Store listing shows **US$19.99 with additional in-app purchases** (per web search of the App Store listing, checked 2026-11-25) — the only paid-upfront app among the six.
- **No Arabic or multilingual claims found anywhere** on the page or in search results.
- **No document/RAG feature mentioned** on the marketing page at all.
- **Weaknesses:** closed source means every functional claim about the main app is unverifiable; Google Play listing (per search snippet) says the app currently targets flagship phones with 8GB+ RAM, a narrower device floor than PocketPal/AnythingLLM/ARA's device-tiered approach.
- **Evidence:** https://www.layla-network.ai/local-llm-android (checked 2026-11-25); https://github.com/l3utterfly/layla-sdk (checked 2026-11-25); App Store/Play Store listing snippets via web search (checked 2026-11-25).

### 2.4 Google AI Edge Gallery

- **Repo:** https://github.com/google-ai-edge/gallery (checked 2026-11-25) — Apache-2.0, **25,457 stars** (the largest community of any competitor reviewed, unsurprising given Google's name on it), 500 open issues, Kotlin 6.27M lines, last push **2026-11-24** with internal Google commits (`PiperOrigin-RevId` references — this is mirrored out of Google's internal monorepo, not developed directly in the open). Release 1.0.23 on 2026-11-04.
- **Strengths (verified from README/source):**
  - **MCP support is real and documented in depth**, not just mentioned: `mcp/README.md` walks through connecting both local (via `supergateway` stdio→StreamableHTTP adapter) and cloud MCP servers (e.g., Google's own Maps Grounding Lite), including per-invocation permission prompts and "always allow" toggles. Google itself labels this **"experimental."**
  - A real **Agent Skills** system with `skills/built-in/` and `skills/featured/` directories in the repo, loadable from a URL or community GitHub Discussions.
  - **Mobile Actions / "Tiny Garden"**: on-device function-calling for phone control, powered by a dedicated **FunctionGemma-270m finetune** — i.e., a purpose-trained small model for device actions, not the chat model doing double duty.
  - **On-device multimodal semantic search** (Instant Media Search, Video Moment Finder) using EmbeddingGemma 2 — real embeddings-based retrieval running locally, which is more advanced than any text-RAG feature found in the other five apps for this specific use case (photo/video libraries, not documents).
- **Weaknesses/limitations (verified):**
  - **No localization found at all.** The entire Android app resolves to a single `Android/src/app/src/main/res/values/strings.xml` in the repo tree — no `values-ar`, no `values-<any locale>` directory exists. Despite 25K+ stars and Google's backing, this is an **English-only UI**, at least as of the current `main` branch.
  - Google explicitly brands it **"an experimental Beta release"** in its own README — i.e., Google itself does not claim production readiness.
  - No document/RAG-over-files feature, no persistent cross-session memory, no conversation branching found.
  - Because commits mirror from an internal Google monorepo, external contributors have limited real influence over roadmap/architecture despite the open license.
- **Evidence:** repo metadata/commits/releases via `gh api repos/google-ai-edge/gallery` (checked 2026-11-25); README https://github.com/google-ai-edge/gallery/blob/main/README.md (checked 2026-11-25); MCP guide https://github.com/google-ai-edge/gallery/blob/main/mcp/README.md (checked 2026-11-25); repo file tree via `gh api .../git/trees/main?recursive=true` (checked 2026-11-25) confirming only one `strings.xml`.

### 2.5 Private Mind (Software Mansion)

- **Repo:** https://github.com/software-mansion-labs/private-mind (checked 2026-11-25) — MIT-style license with embedded ExecuTorch BSD-3-Clause notices ("Other"/non-standard SPDX per GitHub), 416 stars, 31 open issues, last push **2026-11-25 (same day as this research)** — by commit-message detail, this is the most rigorously engineered codebase of the six: commit messages routinely cite exact device models (Pixel 10, Galaxy S20 FE, iPhone 17), measured before/after numbers (e.g., "5 of 12 answers doubled → 0 of 12" for a dedup fix; PSS memory at two context sizes), and explicit "not covered"/"not tested" sections — a level of engineering honesty worth noting as a direct process model, not just a feature list.
- **Strengths (verified from README/source/commits):**
  - **Document chat with source citations**: PDF/TXT/MD/HTML/CSV, on-device embeddings, "every answer links back to the passages it came from" — directly comparable to ARA's planned Knowledge Vault, and currently more mature than ARA's (ARA has no PDF support yet; Private Mind does).
  - **Conversation branching/forking** from any message — not found in any other competitor reviewed except AnythingLLM Mobile's "fork and retry."
  - **Device-tiered context-window selection** (Low/Medium/High/Auto, gated by measured RAM and a per-model "fit check") — conceptually the same device-aware approach ARA already uses for model selection, but Private Mind applies it to context size specifically, with published on-device memory measurements (PSS) backing the claim.
  - **Private web search**: only the search query leaves the device; pages are fetched and read by the phone itself.
- **Weaknesses/limitations (verified):**
  - **ExecuTorch-only engine, locked to a fixed, pre-converted model catalog** (`catalog/model-catalog-v3.json`) hosted entirely under the maintainer's own Hugging Face org (`software-mansion/...`). Unlike AnythingLLM Mobile, PocketPal, or (claimed) Layla, there is no "import your own GGUF" flexibility — users can only run what Software Mansion has already converted to `.pte`.
  - **No localization infrastructure of any kind** — no locale/i18n files anywhere in the repo tree, and zero "arabic"/"RTL" hits via GitHub code search. English-only UI, by source.
  - **No TTS** found in the README's feature list (voice is input-only).
  - The README embeds **third-party ad-zone image placements** from `swm-delivery.com` directly in the project page — an unusual pattern for an "open source, no account, no server" privacy pitch; it's unclear whether these are self-promotional (Software Mansion's own ad network) or a genuine third-party ad integration, and the README does not explain it. Flagged as ⚪ unclear rather than a confirmed privacy concern, since it appears to be README-level display advertising, not in-app tracking.
  - A recent fix (#556, merged shortly before this research) addressed a **2% user-perceived crash rate** on 32-bit-only low-end Android devices that had been shipped broken for a release cycle — a real, admitted reliability miss on exactly the low-end-device segment ARA also targets.
- **Evidence:** repo metadata/commits/releases via `gh api repos/software-mansion-labs/private-mind` (checked 2026-11-25); README https://github.com/software-mansion-labs/private-mind/blob/main/README.md (checked 2026-11-25); commit https://github.com/software-mansion-labs/private-mind/commit/1386a76 (ABI crash fix, checked 2026-11-25); model catalog https://github.com/software-mansion-labs/private-mind/blob/main/catalog/model-catalog-v3.json (checked 2026-11-25).

### 2.6 Qandeel (قنديل)

- **No source code access.** No GitHub repository found under any plausible name/org. This is a closed-source Android app distributed only via Google Play (`com.yazan.qandeel`).
- **Play Store page itself could not be rendered by the fetch tool** (the live listing is a JavaScript-rendered single-page app; direct fetch returned only the page `<title>` — "قنديل - Qandeel - Apps on Google Play" — confirming the app exists, but no body content). This matches the task brief's own expectation that the Play listing "may lack technical depth."
- **Description text was recovered via a search-engine cache of the listing** (checked 2026-11-25), which is the closest available substitute for the listing body. Per that cached text, Qandeel's own listing claims:
  - 🟡 Runs entirely on-device, no constant internet connection, typed text not sent to a server.
  - 🟡 User-selectable open-source models ("Gemma, Qwen, Phi, and more"), loaded by the user, no subscription.
  - 🟡 On-device Whisper speech-to-text.
  - 🟡 "Knowledge Packs" — user-imported text/PDF files that stay on-device.
  - 🟡 RTL Arabic interface with full English support, three themes.
  - 🟡 Built-in "characters"/personas and context memory for longer conversations.
  - 🟡 The listing's own English-locale "last updated" date, per the search cache, is **28 Jul 2026** — roughly four months before this research date, and visibly stale next to every repo-based competitor above (all of which show commits within the last 24 hours to one week).

## 3. ARA's own current state (from `docs/MASTER_PLAN.md` and `docs/ROADMAP_TASKS.md`, not re-verified here)

This section is a summary, not new research — pulled directly from ARA's own honestly-labeled docs so the comparison above isn't one-sided. No ARA capability is stated here beyond what those two files already claim as TESTED/IMPLEMENTED/PLANNED.

**Tested/working, with evidence already in-repo:**
- Local llama.cpp inference with streaming and cancellation — **tested on Linux x86_64 only, never run on an actual Android phone.**

- Dialect/language crosswalk (Egyptian Arabic ⟷ MSA ⟷ English) via a static lexicon + capped learned-alias table (2000 rows), no model training — 20 tests passing.
- User-controlled memory (simple list, explicitly not a graph).
- 20 tools with permissions, confirmation, and limits — core logic tested via CLI + real model; **Android Intent execution is implemented but not device-tested.**
- 9 specialized modes (general assistant, software engineer, security expert, designer, etc.) — security/coding mode quality is honestly flagged as needing a 7B+ model.
- API Hub for cloud providers with a PII-redaction "privacy shield" — tested against a mock server only, no real provider key tested yet.

**The single biggest honestly-flagged gap:** ARA has never been run on a physical Android phone. Every performance number and every "tool execution works" claim is from a Linux x86_64 Codespace or a CLI harness, not a device.

## 4. Evidence-backed opportunities for ARA

Each item below ties to a specific, cited gap found above — not a generic claim.

1. **Arabic localization is a genuinely open lane among the repo-based competitors.** AnythingLLM Mobile ships 17 languages and Arabic isn't one of them (confirmed via `languages.json`); Google AI Edge Gallery, despite 25K+ stars and Google's backing, has exactly one `strings.xml` and no localization system at all (confirmed via repo tree search); Private Mind has zero i18n infrastructure (confirmed via repo tree search + code search for "arabic"/"RTL"). Only PocketPal ships a real Arabic UI translation, and even it leaves some strings untranslated (`"second": "sec"`) inside `ar.json`. ARA's dialect crosswalk (Egyptian/MSA/English, tested, 20 passing cases) is a more linguistically serious treatment of Arabic than anything found in these three apps' own source — but it still needs the Arabic benchmark run across the full model catalog (only 2 of 12 models measured) before this can be claimed with numbers, not just "we have a crosswalk and they don't."

2. **Document chat is split, unevenly, across competitors — and ARA is currently behind the two that have it, ahead of the three that don't.** AnythingLLM Mobile and Private Mind both have working on-device RAG over PDFs with citations (verified in their READMEs); PocketPal, Google AI Edge Gallery, and (per its own marketing page) Layla do not mention document/RAG chat at all. ARA's search is file-format-limited to TXT/MD/CSV/JSON/HTML (T1.1, PDF/DOCX/EPUB still ⬜) — closing that specific gap (PDF first, since that's what both AnythingLLM Mobile and Private Mind already ship) is the most directly comparable, highest-leverage next step, not a hypothetical "better RAG" claim.

3. **At-rest encryption of local conversation/document storage was not found in any of the four open-source competitors' code.** AnythingLLM Mobile and Private Mind had zero "encrypt" hits in GitHub code search; PocketPal's own README tech-stack table places chat history in a plain WatermelonDB with only *secrets* (not chat content) in Keychain. (Caveat: GitHub code search can be incomplete, so this is "no evidence found," not "proven absent.") ARA's own T1.8 (SQLCipher/Keystore encryption of `index.db` and conversations) is still unimplemented too — but if ARA ships it before these competitors do, "your messages are encrypted at rest, not just unsynced" would be a claim none of the four open-source competitors reviewed can currently make about their own shipped apps, based on their own source.

4. **A centrally-audited "Strict Offline Mode" (not just an offline-capable design) appears to be missing industry-wide.** Every competitor reviewed *claims* offline-first operation as a design philosophy, but none of the four open-source ones expose an in-app mechanism that proves or logs what actually left the device per request. ARA's planned T1.7 (Privacy Center with per-request local/cloud/tool logging and a verifiable network-block mode) would be answering a question ("prove nothing left my phone") that these apps currently only answer with prose, not a feature.

5. **Deep OS-level assistant integration (default assistant role, system-wide text-selection actions, share-target) is currently an AnythingLLM Mobile exclusive** among the apps reviewed — none of PocketPal, Layla (per marketing), Gallery, or Private Mind describe anything equivalent. ARA's roadmap doesn't yet have an explicit equivalent item; given ARA's Android-Intent tool execution is already implemented (if undertested on-device), extending it to a default-assistant / selection-toolbar integration is a concretely scoped feature with a working precedent to study (AnythingLLM Mobile's own commit history, e.g. the image-picker and Reanimated crash fixes from building exactly this kind of OS integration, is a useful list of pitfalls to avoid).

6. **MCP support is real only at Google AI Edge Gallery (confirmed, experimental) and claimed-but-unverifiable at Layla.** ARA's roadmap frames its P2 "Skills Ecosystem" as a signed/sandboxed manifest system, which is a different (and arguably safer) model than MCP's open server-connection approach — worth deciding explicitly whether ARA wants MCP-compatibility specifically (to interoperate with the wider MCP tool ecosystem Gallery is tapping into) or stays with its own sandboxed skills design. This is a decision point, not a gap, since Gallery's own README calls MCP "experimental" even inside Google.

7. **Qandeel is the one Arabic-first Android competitor, but its complete lack of verifiable technical documentation is itself the finding.** Every claim about it (RTL interface, Knowledge Packs, Whisper, personas, memory) is Advertised-tier, sourced only from a Play listing that a direct fetch couldn't even render. Its listing's own "last updated" date (28 Jul 2026, per search cache) is roughly four months stale against every repo-based competitor's within-the-week activity — a possible signal of reduced active development, though this is a single weak signal (one cached date), not a verified trend, and should be re-checked before being treated as fact. ARA's differentiation case against Qandeel specifically ("we can prove our Arabic handling and privacy claims because the code and benchmarks are public") is stronger than against any other competitor in this set, precisely because Qandeel offers nothing to verify against.
