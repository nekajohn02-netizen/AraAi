# ARA — الأمان والخصوصية

## المبادئ
1. الخصوصية افتراضيًا: المحادثات، النماذج، القياسات، الصلاحيات، الإعدادات في مساحة التطبيق الخاصة (`filesDir/ara`).
2. الإنترنت يُستخدم فقط لتنزيل نموذج يختاره المستخدم. لا تحليلات، لا رفع.
3. لا أسرار خادم داخل APK.

## المطبّق والمختبر
| الحماية | الدليل |
|---|---|
| الأخطاء لا تحمل محتوى المستخدم أو المسارات | `io_error_does_not_leak_message`، `missing_and_corrupt_files_fail_cleanly` |
| الكتالوج: https فقط، معرفات بلا `/` أو `..`، sha256 إلزامي للتثبيت | اختبارات registry + `bundled_catalog_is_valid_and_fully_verified` |
| التنزيل: تحقق SHA-256 قبل إعادة التسمية، حذف الملف التالف، قفل ضد التكرار، رفض http | 7 اختبارات model-manager بخادم HTTP محلي |
| المحادثات: معرفات آمنة ضد path traversal، كتابة ذرية، تجاهل الملف التالف | `rejects_path_traversal_and_survives_corruption` |
| الأدوات: schema صارم، precheck (https، هاتف، تاريخ)، صلاحيات، تأكيد إلزامي للأثر الخارجي، حد معدل، حد حلقات الوكيل (3) وحد الاستدعاءات (4/دور) | 26 اختبار ara-tools + 6 coordinator |
| مخرجات النموذج غير موثوقة: استدعاء مجهول/مشوه يُرفض، نتائج الأدوات تُعلَّم كبيانات لا تعليمات | `invalid_or_unknown_calls_are_denied`، `malformed_unterminated_and_excess_calls_are_rejected` |
| حقن تعليمات من محتوى ملف (مهما كان موديل مُخترَق يحاول تنفيذها، ومهما كانت الصلاحية "مسموح دائمًا"): صفر تنفيذ صامت عبر الخط الكامل (بحث حقيقي → `guard` → تأكيد) | `injected_document_content_cannot_trigger_a_silent_external_action` (7 هجمات) — T1.9 |
| Strict Offline Mode: صفر محاولة اتصال فعلية (لا بعد فشلها)؛ إعداد فعلي `AraCore::set_strict_offline` يبقى محفوظًا عبر إعادة الفتح — **لا شاشة/مفتاح في واجهة Kotlin بعد** | `strict_offline_mode_never_opens_a_socket` (`ara-cloud`) + 3 اختبارات `ara-ffi` — T1.7، جزئي |
| Kotlin ينفذ فقط قائمة ثابتة من الأدوات، ويعيد فحص https | `HostActions.kt` |
| لا نسخ احتياطي سحابي/نقل أجهزة | `allowBackup=false` + `data_extraction_rules.xml` |
| لا إرسال خفي: الرسائل/المنشورات/المكالمات تفتح التطبيق الهدف والمستخدم يضغط إرسال | ADR-007 |
| مفاتيح API: Keystore AES-256-GCM، لا تُكتب في providers.json، لا تظهر في الأخطاء أو Debug | `api_hub_requires_consent_and_never_stores_keys`، `http_errors_are_mapped_without_leaking_the_key` |
| لا إرسال سحابي بدون موافقة صريحة لكل مزود؛ تغيير العنوان يلغيها | نفس الاختبار + `apiHubEnforcesConsent` (Kotlin) |
| درع الخصوصية يمنع خروج الهاتف/الإيميل/الكارت/الرقم القومي/المفاتيح | `streams_redacts_outgoing_and_restores_incoming` (يتحقق من الطلب الفعلي المرسل) |
| تشفير المحادثات AES-256-GCM (`ara-crypto`، T1.8/ADR-018): الملف الخام على القرص لا يحتوي النص الصريح، المفتاح الخطأ يفشل، تلاعب بالنص المشفَّر يُكتشَف — **لم يوصَل بمفتاح Keystore حقيقي من Kotlin بعد**، و`index.db` غير مُشفَّر بعد | 8 اختبارات `ara-crypto` + 3 اختبارات `ConversationStore` (`encrypted_store_round_trips_and_file_is_not_plaintext_on_disk` وغيرها) — T1.8، جزئي |
| توقيع/تحقق مهارات Ed25519 (`ara-tools::skills`، T2.2a/b/ADR-017): مهارة بلا توقيع أو بتوقيع مُعدَّل بعد التوقيع تُرفض — **لا مفتاح عام حقيقي لـARA مُضمَّن بعد، ولا مهارة ara-verified فعلية** | 7 اختبارات جديدة (`ara_verified_skill_is_rejected_if_any_signed_field_was_edited_after_signing` وغيرها) — T2.2، جزئي |
| استيراد/حذف/حظر مهارات (`AraCore::import_skill`/`delete_imported_skill`/`set_skill_blocklist`، T2.2c/d/ADR-017): ملف مستورَد لا يقدر يدّعي `ara_verified`، مهارة محظورة تختفي فورًا من القائمة بلا إعادة استيراد أو تشغيل — **لا شاشة Kotlin تعرض التحذير بعد** | 7 اختبارات `ara-ffi` — T2.2، جزئي |
| سجل Privacy Center (`AraCore::activity_log`، T1.7/T2.2e): بيانات وصفية فقط (أداة، مهارة، نتيجة، وقت) — **فحص فعلي للبايتات على القرص يثبت غياب النص/نتائج البحث/الحقائق المحفوظة**، سقف 500 إدخال — **لا شاشة Kotlin تعرضه بعد** | 6 اختبارات `activity_log` + اختبار تكامل في `documents_and_memory_through_core_and_tools` — T1.7/T2.2، جزئي |
| سياسة محتوى لأي أداة توليد وسائط مستقبلية (`ara-tools::content_policy`، T2.6، طلب صاحب المشروع): يرفض طلبات توليد الموسيقى/الأغاني (قرار سياسة، لا حدًا تقنيًا) والمحتوى الجنسي/الإباحي — مطابقة كلمات مفتاحية best-effort بتطبيع عربي (نفس تحذير درع الخصوصية: ليست تصنيفًا ذكيًا). **لا أداة توليد وسائط موجودة بعد لتستخدمه** — جاهز كـ precheck ليوم تُبنى | 6 اختبارات — T2.6، لم يبدأ التوليد نفسه |

## الأذونات في Android
- `INTERNET`: تنزيل النماذج، والمزودين السحابيين فقط بعد موافقة المستخدم.
- `SET_ALARM`: إذن عادي لـ Intents المنبه.
- لا أذونات حساسة (لا جهات اتصال، لا SMS مباشر، لا كاميرا، لا Accessibility).

## مخطط لاحقًا
- وصل تشفير المحادثات (أعلاه) بمفتاح Keystore حقيقي من Kotlin، وتشفير `index.db` (أصعب — على مستوى الحقل لا الملف، لأن FTS5 يحتاج نصًا مُطبَّعًا قابلًا للفهرسة). لا نفترض أن Keystore يشفر الملفات تلقائيًا.
- **مهارات الطرف الثالث (T2.2، تصميم كامل في `docs/ARCHITECTURE.md` ADR-017؛ T2.2a/b مُنفَّذتان جزئيًا أعلاه):** المهارة بيانات (id/تعليمات/قائمة أدوات موجودة فعلًا) لا برنامج — لا كود ولا سكريبت يُنفَّذ، فلا حاجة لصندوق (sandbox) تنفيذي من الأساس. تعليماتها غير موثوقة دائمًا ولا توسّع صلاحيات أي أداة (نفس قاعدة T1.9). طبقات ثقة: مدمجة ← موثّقة من ARA وموقَّعة (عدد صغير مُراجَع، لا سوق ذاتي الخدمة مفتوح) ← مستوردة يدويًا بتحذير صريح. كل تحديث يُعاد فحص توقيعه ويُعرَض فرقه (الأدوات الجديدة) قبل التفعيل — لا ثقة موروثة من نسخة سابقة، **ومُختبَر فعليًا** أن تعديل `instructions`/`tools` بعد التوقيع يُبطِله. **الباقي:** قائمة حظر/إلغاء موقّعة (T2.2d)، تتبّع Privacy Center (T2.2e)، واستيراد يدوي بتحذير في الواجهة (T2.2c) — لا شيء منها مبني بعد. **الدافع المباشر:** بحث مُوثَّق (2026-11-25) لحملات تسميم سوق المهارات `ClawHub` (أكثر من ألف مهارة خبيثة عبر عدة تدقيقات مستقلة، سكريبتات تعمل بصلاحيات المستخدم الكاملة وتقرأ متغيرات البيئة) — التفاصيل في `research_notes/تحليل Instinct ومنصات المهارات/skills_marketplace_security.md`.
- **درس Instinct (منافس سحابي، بيتا خاصة أغسطس 2026، تفاصيل في `research_notes/تحليل Instinct ومنصات المهارات/instinct_profile.md`):** موافقة واحدة عريضة على إيميل/تقويم/رسائل/شاشة/صوت بلا تأكيد لكل فعل (أرسل إيميل فعليًا بلا تأكيد مسبق — حادثة موثَّقة) وبلا حذف موثوق بعد قطع الاتصال (حادثتان موثَّقتان) — هذا تمامًا ما يمنعه `dispatch()` الحالي في ARA (تأكيد إلزامي لأي أثر External حتى تحت صلاحية "دائمًا") و**مُختبَر فعليًا من قبل** (T1.9، 7 هجمات، صفر تنفيذ صامت) — لا تغيير مطلوب هنا، فقط توثيق الفرق بالمصدر عند أي مقارنة علنية مستقبلية.
- Supabase: RLS واختبارات عزل، التحقق من الاشتراك على الخادم فقط.
- Telegram Bot: التحقق من بيانات المصادقة على الخادم، تأكيد العمليات الحساسة.
