## ما يعمل فعلًا (مع الدليل)
- **اختيار النموذج حسب الجهاز**: استبعاد بالرام المتاحة/المساحة/اللغة/السياق، ثم ترتيب بطبقات (usable ≥ 8 tok/s مع هامش رام > tolerable ≥ 2 > slow). السرعة تُقدّر من عرض نطاق الذاكرة وتُعايَر من القياسات الفعلية.
- **قياسات حقيقية على Codespace (4 أنوية x86_64، CPU)**:

| النموذج | تحميل | أول token | سرعة التوليد | ذاكرة |
|---|---|---|---|---|
| Qwen2.5-0.5B Q4_K_M | 0.35 ث | 0.20 ث | 25 tok/s | ~0.6 GB |
| Qwen2.5-1.5B Q4_K_M | 1.26 ث | 0.46 ث | 18.7 tok/s | ~1.9 GB |

- **الأدوات عبر نموذج حقيقي** (`ara agent`): 1.5B نفّذ صحيحًا: الحاسبة (351)، تحويل الوحدات، واتساب برقم ونص (مع طلب تأكيد)، منبه 06:30، مؤقت 10 دقائق، الكشاف. 0.5B **غير صالح للأدوات** (أدوات خاطئة، رد بالصينية) ⇒ يُنصح بـ 1.5B فأعلى للمهارات.
- **التطبيق**: شاشات المحادثة (Streaming، إيقاف، تأكيد الإجراءات، السجل)، النماذج (فحص الجهاز، ترتيب، تنزيل/استئناف/إلغاء، استخدام، قياس، حذف)، المهارات والصلاحيات، الإعدادات (حد المساحة، حجم السياق). عربي/إنجليزي وRTL.

## المخاطر والمتبقي
1. لم يُشغّل أي شيء على هاتف حقيقي بعد. المطلوب: `adb install app-debug.apk` على هاتف arm64 وقياس الأداء الفعلي.
2. حجم APK التجريبي كبير لأنه يضم معماريتين؛ للتوزيع نستخدم AAB (Play يرسل معمارية واحدة).
3. إعادة استخدام KV cache تعمل فقط حين يبقى بداية الـ prompt ثابتة؛ تغيّر المهارات الموجّهة يغيّر الـ system prompt فيقلل الاستفادة.
4. أوصاف اللغات في الكتالوج من وثائق الناشر، لم نقيّم جودة العربية بعد.

## نتائج G2.5 / G5 الجديدة
- **إعادة استخدام KV cache**: رسالة متابعة (199 token) — أول token خلال **286 ms بدل 3230 ms** (Qwen2.5-1.5B). الناتج مطابق حرفيًا مع وبدون cache (اختبار حتمي).
- **البحث في الملفات + RAG** على ملف عربي حقيقي بـ Qwen2.5-1.5B: 5/5 إجابات صحيحة بأرقام أسطر صحيحة (مثلًا «الميزانية الكلية ٨٥٠٠٠ جنيه (plan.md:8)»)، وسؤال غير موجود في الملف ⇒ «لم أجد» بدل الاختلاق.
- قبل RAG الحتمي: النموذج الصغير تجاهل أداة البحث وقال «لا أستطيع العثور» ⇒ القرار: البحث يتم من النواة قبل النموذج.

## الإضافات الأخيرة
- **الكتالوج 12 نموذجًا** (كلها Apache-2.0 وsha256 موثّق): أُضيف Qwen2.5-Coder 1.5B/7B (برمجة)، IBM Granite 3.3 2B و4.0 Micro (أدوات، تدعم العربية)، SmolLM3 3B.
- **Kimi K3**: موجود على Hugging Face بحجم **2.78 تريليون معامل** ⇒ مستحيل محليًا على أي هاتف (>1.4TB حتى بـ 4-bit). مدعوم عبر API Hub بمفتاح المستخدم.
- **أوضاع متخصصة (9)**: مساعد عام، مهندس برمجيات، خبير أمن (دفاعي)، مصمم، كاتب محتوى وتسويق، معلم، مترجم، محلل أعمال، منظم شخصي. كل وضع: تعليمات + حرارة + مهارات دائمة + نوع النموذج المطلوب (code/chat/reasoning) ⇒ ترشيح نموذج مناسب.
- **API Hub**: Kimi/Moonshot، DeepSeek، OpenAI، OpenRouter، Groq، Mistral، Together أو أي واجهة OpenAI-compatible. المفتاح مشفّر بـ Android Keystore (AES-256-GCM) ولا يُكتب في ملفات النواة. موافقة صريحة لكل مزود، وتغيير العنوان يلغي الموافقة. النموذج السحابي يمر بنفس الـ Coordinator (أوضاع، RAG، أدوات، تأكيدات).
- **درع الخصوصية**: قبل الإرسال يستبدل الهواتف والإيميلات والكروت (Luhn) والرقم القومي المصري وIBAN والمفاتيح السرية بـ `[PHONE_1]`… ويعيدها في الرد على الهاتف (حتى لو انقسمت أثناء البث).
- ملاحظة صادقة: مع Qwen2.5-1.5B وضع الأمن يحدد SQL injection لكن الحل المقترح ضعيف ⇒ الأوضاع المتخصصة تحتاج Coder-7B أو نموذج سحابي لدقة عالية.

2. ~~استخراج PDF~~ — تم (نص + استشهاد بالصفحة، `docs/ARCHITECTURE.md` ADR-014). التالي: البحث الدلالي (embeddings محلية، T1.2b) ومجموعة تقييم استرجاع حقيقية (T1.3).
