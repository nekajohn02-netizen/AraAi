## 0. نقطة حاسمة لازم تُقال بصراحة قبل أي شيء تاني

الطلب الأصلي شمل: *"تتحكم في أي جهاز يتوصل فيه او اي جهاز مربوط
بالانترنت"*. هذا البند **مرفوض كما وُرد حرفيًا**، ومُعاد تحديد نطاقه هنا
بدل تجاهله بصمت:

- **الفرق الجوهري:** "جهاز الهاتف نفسه" أو "جهاز سمارت-هوم قام المستخدم
  بإقرانه صريحًا بحسابه" هو نطاق منتج حقيقي (آرا بتعمل ده جزئيًا فعلًا —
  قسم 12 تحت). "أي جهاز متصل بالإنترنت" بلا تخصيص هو تعريف تقني لقدرة
  **وصول/تحكم غير مُصرَّح به على أجهزة لا يملكها ولا يديرها المستخدم** —
  هذا نفس الوصف الهيكلي لشبكة بوت نت (botnet) أو برمجية خبيثة، بصرف
  النظر عن النية. لن أصمم أو أقترح أي بنية لهذا — لا كأداة، لا كمهارة،
  لا كمجلد مستقبلي.
- **هذا ليس قرارًا تعسفيًا من عدم — المشروع نفسه عنده نفس القاعدة
  مكتوبة من قبل:** `docs/EXPANSION_BLUEPRINT.md` الفئة N يقول صريحًا
  *"غير واقعي وما ينفعش نعِد بيه... وصول root/kernel مباشر للهاردوير...
  افتراض إن الهاتف يشتغل زي كمبيوتر/سيرفر"*، و`docs/ARCHITECTURE.md`
  ADR-006 يمنع أي "framework تحكم عام" في الأجهزة. وفي
  `docs/COMPETITIVE_ANALYSIS.md` §2.8 فيه حالة حقيقية موثّقة (Instinct)
  لعميل سحابي وسّع صلاحياته على حسابات المستخدم بلا بوابة تأكيد واضحة —
  النتيجة حوادث خصوصية حقيقية موثّقة من TechCrunch ([Spear Street
  Technology's Instinct](https://techcrunch.com/2026/08/24/instincts-powerful-ai-assistant-is-raising-privacy-and-security-concerns/),
  تم الفحص 2026-11-25). آرا بُنيت أصلًا **ضد** هذا النمط بالذات
  (`dispatch()` يفرض تأكيد على أي أثر External، بلا استثناء، مُختبَر ضد
  7 هجمات).
- **النطاق المُعاد تحديده لباقي هذا المستند:** "تحكم في جهاز" = جهاز
  المستخدم نفسه (الهاتف) عبر Android APIs الرسمية، أو جهاز سمارت-هوم
  داخل شبكة المستخدم المحلية **بعد إقران/موافقة صريحة لكل جهاز وبوابة
  تأكيد لكل فعل**. مفيش استثناء لده، ومفيش "وضع متقدم" يتجاوزه.

هذا التوضيح مش رفض للطلب — القسم 12 تحت فيه خطة IoT جادة وموسّعة فعليًا،
بس داخل الحد ده بالتحديد.

**الفجوة الحقيقية المفيدة (✅ قابلة للبناء):** وضع "رائد أعمال" الموجود

## 3. التسويق وصناعة المحتوى

**الموجود في السوق:** Sprout Social (تقارير، $249/شهر لـ5 حسابات)،
Buffer (يكيّف المنشور لكل منصة)، Hootsuite (محتوى + جدولة + صندوق وارد
موحّد)، Canva (إنشاء بصري)، Brand24 (رصد العلامة) — كل ده SaaS سحابي
بحسابات OAuth حقيقية لكل منصة ([Zapier](https://zapier.com/blog/best-ai-social-media-management),
فُحص 2026-11-26).

**حالة آرا:** `docs/MASTER_CAPABILITY_REGISTRY.md` الفئة BJ/BC تقول
صريحًا إن آرا عندها وضع "كاتب محتوى وتسويق" (نص فقط، محلي)، بس **مافيش
نشر فعلي لأي منصة** (الفئة G الأصلية = "unbuilt"، تحتاج تسجيل OAuth
حقيقي لكل منصة لم يُعمل).

**الحكم:**
- ✅ **صياغة المحتوى محليًا** (منشورات، كابشن، خطط محتوى، تقويم تحريري
  كملف محلي) — موجودة بالفعل كوضع، تحتاج تعميق فقط (قوالب لكل منصة،
  حدود الحروف، نغمة اللهجة المصرية مقابل الفصحى).
- 🟡 **النشر الفعلي عبر Intent (زي واتساب/تيليجرام الموجودة)** —
  بعض منصات السوشيال بتدعم Share Intent من الأندرويد (مثلًا فتح تطبيق
  إنستجرام/فيسبوك بمحتوى جاهز، المستخدم يضغط نشر هو) — نفس فلسفة
  ADR-007 الموجودة (المستخدم يضغط "إرسال" بنفسه). هذا **ليس** نشرًا
  تلقائيًا كامل (مفيش API رسمي مجاني لمعظم المنصات للمستخدم العادي)،
  لكنه خطوة واقعية فورية.
- ❌ **جدولة/نشر تلقائي بلا تفاعل المستخدم عبر API رسمي لكل منصة** —
  يحتاج تسجيل Developer App لكل منصة (Meta/X/LinkedIn/TikTok)، مراجعة
  أمنية من كل شركة، وصيانة دائمة لكل تغيير API — عبء هندسي مستمر غير
  متوافق مع "مساعد محلي بلا سيرفر خلفي". **البديل الصادق:** لو المستخدم
  عنده مفتاح/توكن API لمنصة معينة بنفسه (BYO، نفس فلسفة API Hub)، آرا
  تقدر تستخدمه — **لا يُبنى أي اتصال مباشر بلا موافقة ومفتاح المستخدم
  نفسه.**

## 6. متابعة السوق وتحليل المنافسين

**الموجود في السوق:** Semrush/Ahrefs/Similarweb (SEO وحركة الموقع)،
Meltwater/Brandwatch (رصد إعلامي)، Visualping (رصد تغييرات الصفحات،
مجاني لـ150 فحص/شهر)، أدوات AI للتجميع والتلخيص فوق هذه المصادر
([ClickUp](https://clickup.com/blog/ai-tools-for-competitor-analysis/),
فُحص 2026-11-26). كل هذه أدوات SaaS بفهرسة ويب مستمرة وبنية تحتية ضخمة.

**حكم آرا:** `docs/MASTER_CAPABILITY_REGISTRY.md` الفئة X/BK تقول
صريحًا: فيه وضع "بحث" موجود، **لكن آرا مش بتتصفح الويب فعليًا** —
`web_search` بيفتح المتصفح للمستخدم بس، وهذا مكتوب صراحةً داخل تعليمات
الوضع نفسه (منع الادّعاء بقراءة نتائج حقيقية). هذا أهم فجوة في هذا
المجال بالكامل.

**الحكم بالتفصيل:**
- ❌ **آرا تبني محرك فهرسة/رصد ويب خاص بيها** — عبء هندسي ضخم (crawler،
  تخزين، تحديث مستمر) يكرر منتجات متخصصة بمئات المهندسين؛ خارج نطاق
  مساعد محلي على هاتف.
- ✅ **نفس نموذج API Hub: BYO key لأدوات رصد موجودة فعلًا** — لو
  المستخدم عنده اشتراك/مفتاح API في Similarweb أو Semrush أو حتى
  Visualping، آرا تقدر تستدعي الـAPI بتاعهم وتلخّص النتيجة محليًا —
  **هذا هو "التكامل مع أدوات" الحقيقي المطلوب**، لا إعادة بناء أدوات
  موجودة.
- ✅ **تنفيذ البحث الفعلي عبر المتصفح لاحقًا (T يحتاج قرار معماري
  منفصل، مش جزء من هذا المستند)** — لو آرا قررت فعلًا تتصفح الويب
  (وليس فقط تفتح المتصفح للمستخدم)، هذا قرار أمني وهندسي كبير بما
  يكفي ليستحق ADR مستقل، مش بندًا عابرًا هنا.

## 7. القدرة البرمجية مقارنةً بموديلات تانية

**البحث (2026-11-26، أرقام متضاربة بين المصادر — تُقرأ باحتياط):**
على SWE-bench Verified، تقارير مختلفة تضع Claude Opus بين ~88% و~97%
(تراكر غير مؤكد)، GPT-5.5/5.6 قريب جدًا (~88–96%)، Gemini 3.1 Pro
~79–80%، وSonnet 5 بين ~68% و~82% حسب المصدر والـharness المستخدم
([Simon Willison](https://simonwillison.net/2026/feb/19/swe-bench),
[vals.ai](https://www.vals.ai/benchmarks/swebench), فُحصا 2026-11-26).
البحث نفسه بيحذّر إن المصادر الثانوية متضاربة ولازم مراجعة اللوحة
الرسمية مباشرة لأي رقم نهائي.

بالنسبة للموديلات المحلية الصغيرة (التي تشغّلها آرا على الهاتف):
المصادر متفقة إن الموديلات الصغيرة (3–9B) كفاية لمهام برمجة روتينية
(تصحيح أخطاء صغيرة، سكريبتات، نماذج بسيطة)، لكنها **تضعف بشدة** في
الاستدلال الطويل متعدد الخطوات، والسياق الكبير (>128K)، والتعامل مع
مستودعات كبيرة ([EPAM](https://www.epam.com/insights/ai/blogs/qwen-vs-gemma-local-llm-coding-agent-test),
[towardsdatascience](https://towardsdatascience.com/how-to-choose-between-small-and-frontier-models/),
فُحصا 2026-11-26).

**حكم آرا (صادق، لا تضخيم):**
- آرا نفسها موثّقة بصدق في `MASTER_PLAN.md`: *"وضع الأمن [بموديل
  1.5B] يحدد SQL injection لكن الحل المقترح ضعيف ⇒ الأوضاع المتخصصة
  تحتاج Coder-7B أو نموذج سحابي لدقة عالية"*. هذا ينطبق بنفس القوة على
  وضع "مهندس برمجيات".
- **الفرق الهيكلي عن كلود/GPT/Gemini: آرا بموديل محلي (0.5B–7B على
  الهاتف) أضعف بفارق كبير وموثّق من أي موديل سحابي حديث في أي مهمة
  برمجة غير تافهة — هذه ليست مسافة قريبة.** الوعد الواقعي الوحيد: **API
  Hub الموجود فعلًا** (Kimi/DeepSeek/OpenRouter/Groq/Mistral/Together
  أو أي واجهة OpenAI-compatible) يسمح للمستخدم يوصّل مفتاحه الخاص بموديل
  سحابي قوي (حتى Claude/GPT لو المزود OpenAI-compatible) ويحصل على جودة
  قريبة من الأفضل في السوق — **لكن ده لسه غير مُختبر بمفتاح حقيقي**
  (موثّق في `MASTER_PLAN.md`).
- ✅ **أولوية حقيقية:** اختبار API Hub بمزود حقيقي (ليس وهميًا) +
  قاعدة واضحة للمستخدم: "لمهمة برمجة حقيقية، استخدم مزود سحابي عبر API
  Hub، لا الموديل المحلي" — صدق بدل وعد بأداء غير موجود.

## 8. الأمن السيبراني

**الموجود في السوق:** فئة "pentesting agentic" حقيقية ونشطة 2026 —
XBOW (يُنفّذ تقارير تصل لـ48 خطوة هجوم وآلاف الهجمات التلقائية لكل
تكليف، $4000/اختبار)، CAI (مفتوح المصدر، أكثر من 300 موديل مدعوم)،
PentAGI (نظام متعدد الوكلاء: باحث/مطوّر/منفّذ)، Novee وHadrian Nova
وNodeZero ([Beagle Security](https://beaglesecurity.com/blog/article/agentic-pentesting-tools.html),
فُحص 2026-11-26). هذه أدوات **هجومية موجّهة لفرق أمن محترفة** تعمل باذن
صريح على أهداف محددة.

**حكم آرا — فرق جوهري في الهوية، لا مجرد فجوة قدرة:**
- ❌ **آرا لا ولن تكون أداة هجوم/استغلال تلقائي.** هذا ليس قصورًا يُسد —
  آرا مساعد شخصي على هاتف المستخدم، لا بيئة pentest معتمدة. بناء "شنّ
  هجوم آلي على هدف" داخل تطبيق شخصي = نفس فئة الخطر المرفوضة في إرشادات
  هذه الجلسة نفسها (أدوات مزدوجة الاستخدام تحتاج سياق تفويض واضح —
  هاتف شخصي عادي ليس هذا السياق).
- ✅ **ما هو منطقي وآمن:** آرا عندها فعلًا وضع "خبير أمن (دفاعي)" —
  هذا الاتجاه الصحيح: فحص **جهاز المستخدم نفسه** (`SecurityScreen.kt`
  الموجودة — جذر الجهاز، صلاحيات التطبيقات، تحديثات، إعدادات خصوصية)،
  شرح ثغرات معروفة (SQLi، XSS...) لمن يسأل عنها تعليميًا، ومراجعة كود
  المستخدم الخاص (لو لصقه في محادثة) — **كل ده دفاعي بالكامل، لا هجوم
  على هدف تالت.**
- 🟡 **توسعة واقعية ومحدودة النطاق:** "مساعد أمن للمطوّر على مشروعه
  الخاص" — مراجعة كود محلي، قوائم فحص OWASP، توليد تقرير ثغرات على ملفات
  المستخدم نفسه (شبيه بـ `/code-review` و`claude-security` الموجودين في
  بيئة Claude نفسها كمصدر إلهام — **مراجعة لا استغلال**). هذا تحت
  `ara-tools` الموجودة فعلًا (أداة قراءة ملفات + تحليل نصي)، لا يحتاج
  بنية جديدة.

## 9. ريادة الأعمال — الدعم العملي لا الأتمتة الكاملة

الوضع الموجود فعلًا (`MASTER_PLAN.md`, 2026-11-25): "رائد أعمال وبحث
وظائف" — بحث عن وظائف، مراجعة سيرة ذاتية، تحليل سوق/منافسين (نظريًا، مع
تنويه صادق إن آرا لا تتصفح فعليًا). هذا أساس جيد يحتاج تعميق محدد، لا
توسعة غير محدودة:

| الحاجة | الحكم | التفصيل |
|---|---|---|
| مسودة خطة عمل / نموذج Business Model Canvas كملف محلي | ✅ | نص بس، من الموديل + ذاكرة المستخدم — لا بيانات خارجية مطلوبة |
| حساب تسعير/هامش ربح/نقطة التعادل | ✅ | `calculator` الموجودة فعلًا كأداة — رياضة بسيطة، لا حاجة جديدة |
| تحليل سوق حقيقي بأرقام فعلية | 🟡 | محتاج تصفّح ويب فعلي (غير موجود) أو BYO API لأداة بحث سوق — نفس حكم §6 |
| مطابقة مستثمرين/عملاء محتملين | ❌ | يحتاج قاعدة بيانات تواصل خارجية ضخمة (نفس فئة Crunchbase/ZoomInfo) — خارج نطاق مساعد محلي |
| تذكير/جدولة مهام رائد الأعمال | ✅ | Missions (WorkManager) الموجودة فعلًا — لا جديد |

## 10. مستودع مهارات Claude كمصدر إلهام → مقترح آرا

هذه البيئة نفسها (Claude Code) فيها مكتبة مهارات ضخمة منظّمة بالدومين —
المستخدم طلب تحديدًا الاستفادة منها. الجدول التالي يربط كل فئة حقيقية
موجودة في هذا المستودع (أسماء المهارات كما ظهرت في `<system-reminder>`
هذه الجلسة) بمقترح مهارة محلية لآرا، مع حكم صريح على الجدوى:

| فئة Claude (أمثلة مهارات حقيقية في المستودع) | مقترح آرا المحلي | الحكم |
|---|---|---|
| `small-business:*` (business-pulse, cash-flow-snapshot, invoice-chase, payroll-prep) | مهارة "لوحة نبض تجاري" محلية: تلخيص ملفات محاسبة/فواتير يستوردها المستخدم بنفسه (نفس `import_document` الموجودة) | ✅ لا بيانات خارجية، بس تحليل نص محلي |
| `marketing:*`, `small-business:content-strategy`, `social-content-engine` | توسعة وضع "كاتب محتوى" الموجود: قوالب لكل منصة + تقويم تحريري محلي | ✅ موجود جزئيًا، يحتاج تعميق فقط |
| `sales:*` (crm-hygiene-check, pipeline-review, lead-triage) | **❌ غير مناسب** — يفترض CRM سحابي متصل؛ آرا بلا حساب/سيرفر | ❌ تعارض مع هوية المنتج |
| `supermetrics-marketing:*` (ad-fatigue, budget-pacing, roas-report) | مهارة "تقرير أداء إعلانات" عبر BYO API مفتاح المستخدم لمنصة إعلانات يملكها | 🟡 ممكن لاحقًا، نفس نموذج API Hub |
| `finance:*` (variance-analysis, journal-entry, reconciliation) | **❌ خارج النطاق** — محاسبة شركة تحتاج دقة/مراجعة قانونية لا موديل صغير على هاتف يضمنها | ❌ NOT_APPLICABLE، نفس منطق MASTER_CAPABILITY_REGISTRY BO |
| `legal:*` (review-contract, nda-review) | مهارة "ملخص عقد" (تنبيه: ليس استشارة قانونية) — نص فقط، تحذير صريح في الواجهة | 🟡 بحدود صريحة: "هذا ليس استشارة قانونية" |
| `data:*` (analyze, sql-queries, statistical-analysis) | أداة "تحليل ملف بيانات محلي" (CSV/JSON الموجودة فعلًا في `search_documents`) | ✅ تمديد بسيط لما هو موجود |
| `engineering:*` (code-review, debug, architecture) | وضع "مهندس برمجيات" الموجود — يحتاج Coder-7B/سحابي (§7) | 🟡 موجود، الجودة محدودة بالموديل |
| `claude-security:*` | وضع "خبير أمن دفاعي" — مراجعة لا استغلال (§8) | 🟡 بحدود §8 الصريحة |
| `operations:*` (runbook, process-doc, status-report) | مهارة "تقرير حالة مهمة" — تستخدم Missions الموجودة فعلًا | ✅ تمديد بسيط |
| `productivity:*` (task-management, memory-management) | الذاكرة الموجودة فعلًا (`add_memory`) — توسعة لقوائم مهام منظّمة | ✅ تمديد مباشر |
| `customer-support:*` (ticket-triage, draft-response) | مهارة "صياغة ردود عملاء" نصية — لو المستخدم تاجر صغير بيردّ بنفسه | ✅ نص فقط، لا تكامل CRM |

**الخلاصة من هذا الجدول:** مستودع Claude غني بمهارات تفترض **اتصال
سحابي دائم بأنظمة شركة** (CRM، محاسبة، إعلانات). الفئات القابلة
للاستلهام الحقيقي لآرا هي **بالضبط تلك التي تعمل على ملفات/نص محلي بلا
حساب خارجي** — هذا هو الفلتر الصحيح، لا "كل فئة موجودة في كلود يجب أن
توجد في آرا".

## 12. قسم خاص: IoT — الأساس الموجود والتوسعة الواقعية

هذا هو المجال المطلوب تحديدًا كـ"قوة عملاقة" — والحقيقة إن آرا عندها
فعلًا أساس حقيقي هنا (`core/crates/ara-smarthome`, ADR-020، 2026-11-25/26)
أقوى بكتير من أي مجال تاني في هذا المستند. البحث (2026-11-26) يدعم
بالضبط الاتجاه المعماري الموجود:

- 🟢 **Matter يعمل محليًا بلا إنترنت/سحابة فعليًا** — موثّق من وثائق
  Home Assistant نفسها: *"Matter products run locally and always allow
  local control... without the need for any internet connection"*
  ([home-assistant.io/integrations/matter](https://www.home-assistant.io/integrations/matter/),
  فُحص 2026-11-26) — هذا يدعم مباشرة فلسفة آرا (hub محلي، لا سحابة
  جديدة تُبنى).
- 🟢 **Thread عنده تدوير مفاتيح أمني مدمج** عند اختراق الشبكة
  ([Homey wiki](https://homey.app/en-ie/wiki/thread-network-security-and-encryption-explained),
  فُحص 2026-11-26).
- 🟢 **Zigbee2MQTT أمنه = تحصين MQTT broker نفسه** (مصادقة، TLS) — دليل
  تحصين كامل موجود ([privatehomelab.com](https://privatehomelab.com/zigbee2mqtt-mosquitto-mqtt-broker-security-hardening/),
  فُحص 2026-11-26) — مرجع هندسي جاهز لو اتبنى `mqtt_client.rs`.
- ⚪ **تحذير حقيقي من البحث:** بعض الأجهزة "المحلية" فعليًا بترسل
  لسحابة الشركة المصنّعة حتى لو البروتوكول يدعم التحكم المحلي — قطعها
  بالفايروول ما بيكسرش التحكم المحلي، بس بيكسر التكامل مع المساعدات
  الصوتية/الوصول عن بعد. هذا تنويه يستحق ظهوره في واجهة آرا نفسها
  ("بعض أجهزتك قد تتصل بسحابة الشركة المصنّعة بغض النظر عن إعدادات آرا").

**خطة توسعة M (تمتد فوق M1–M3 الموجودة في `EXPANSION_BLUEPRINT.md`،
لا تستبدلها):**

| # | الميزة | الحكم | التفصيل |
|---|---|---|---|
| M4 | عميل MQTT عام (`mqtt_client.rs` في `ara-smarthome`) | ✅ | يوسّع تغطية الأجهزة لمن يشغّل Zigbee2MQTT بنفسه، بنفس فلسفة "تكلّم hub موجود، لا تعيد بناء البروتوكول" — المستخدم يدخل عنوان/بيانات الـbroker الخاصة به بنفسه (BYO، نفس نمط API Hub/M1) |
| M5 | سجل أجهزة مقرونة صريح (`device_registry.rs`) | ✅ قرار أمني لا تفاوض | كل جهاز يظهر لآرا لازم يكون ناتج استدعاء المستخدم لـ`devices()` من الـhub الخاص به — **لا فحص شبكة (network scan) لاكتشاف أجهزة لم يطلبها المستخدم** |
| M6 | دعم Matter عبر Home Assistant (بدل بروتوكول مباشر) | 🟡 لاحقًا | يستفيد مجانًا من دعم Matter الموجود فعلًا داخل Home Assistant — لا حاجة لآرا تنفّذ Matter stack بنفسها |
| M7 | تنبيه واجهة "بعض أجهزتك قد تتصل بسحابة خارجية" | ✅ | شفافية بسيطة، لا كود جديد كبير — جزء من شاشة SmartHome الموجودة |

**تذكير أخير يُغلق هذا القسم:** كل الموسّع هنا يمر من **نفس** بوابة
التأكيد الإلزامية (ADR-006) المطبّقة فعلًا على M1–M3 — توسعة التغطية لا
تعني تخفيف الحراسة أبدًا.
